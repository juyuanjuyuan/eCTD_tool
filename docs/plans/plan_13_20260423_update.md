## 0. 背景与问题陈述

本计划汇总 2026-04-24 客户反馈及 Excel 对照分析发现的 **3 个结构性缺口**，统一在此规划后续实施。

### 0.1 来自 Excel 对齐分析（已决策）
| 检查项 | 结论 |
|---|---|
| 模块 2-5 目录结构 vs Excel 4 个 sheet 引用的章节 | **结构无需改动**（缺失 0，"多余"均为中间分类节点） |
| 2.3 element name 不一致 | Excel 笔误，模板正确，不改 |
| 3.2.R.2 批记录（IVD sheet 提及） | 当前 `EXTENSION_POINT` 机制已覆盖，不改 |

### 0.2 来自客户反馈的新需求（本计划核心）
> **"有些药的申请可能有多个原料药需要填入信息，所以在目录那里应该得支持添加像原料药的这种节点"**

对照 ICH DTD `reference/eCTD技术规范V1.1附件包/附件2-1：ICH DTD文件/ich-ectd-3-2.dtd` 权威定义：

| DTD 元素 | 重复性 | 区分属性 | 含义 |
|---|---|---|---|
| `m2-3-s-drug-substance` | `*` 可多次 | `substance` + `manufacturer` REQUIRED | 模块 2.3.S 原料药概述（多原料药） |
| `m2-3-p-drug-product` | `*` 可多次 | `product-name` / `dosageform` / `manufacturer` IMPLIED | 模块 2.3.P 制剂概述（多制剂） |
| `m2-7-3-summary-of-clinical-efficacy` | `*` 可多次 | `indication` REQUIRED | 模块 2.7.3 临床有效性总结（多适应症） |
| `m3-2-s-drug-substance` | `*` 可多次 | `substance` + `manufacturer` REQUIRED | 模块 3.2.S 原料药数据（多原料药） |
| `m3-2-p-drug-product` | `*` 可多次 | `product-name` / `dosageform` / `manufacturer` IMPLIED | 模块 3.2.P 制剂数据（多制剂） |
| `m5-3-5-reports-of-efficacy-and-safety-studies` | 父级 `?` 单次，但自身 `indication` REQUIRED | `indication` REQUIRED | 模块 5.3.5 有效性/安全性报告按适应症分 |

**当前实现缺陷**：`SequenceNode` 模型虽已有 `substance/manufacturer/productName/dosageForm/indication` 字段（`schema.prisma:308-313`），但 `SequenceNode` 与 `CtdTemplateNode` 在同一 Sequence 下是**一对一**关系（通过 `@@index([sequenceId]) + @@index([templateNodeId])`，业务约束上每个 templateNode 只实例化一次），**无法承载"一个申请多个原料药"**的场景。

### 0.3 来自 completeness 分析的 schema 约束
| 发现 | 影响 |
|---|---|
| `CtdCompletenessRule` 没有 `sequenceTypeCodes` 字段 | 非首次序列（回复 cnsqt2 / 撤回 cnsqt3）也会触发首次提交规则，产生误报 |
| 没有 `productTypeCodes` 字段 | MAH 变更、IVD 子场景、化学药品/生物制品分化无法精确规则 |
| `cn-1-11` 作为 section 容器被列为 REQUIRED | 当前 validator 若对 SECTION 节点按"叶元素非空"判断会误判，需要"至少一个子叶节点非空"语义 |

## 2. WP-13.1 详细设计 — 多实例节点

### 2.1 术语定义
- **可重复模板节点** (repeatable template node)：`CtdTemplateNode.isRepeatable = true` 的节点，对应 DTD 中 `*` 允许多次出现的 5 个 element
- **实例组** (instance group)：同一 sequence 下同一 repeatable template node 的所有 SequenceNode 实例
- **实例键** (instance key)：区分同一实例组内不同实例的骨架属性组合（如 `substance=阿莫西林 + manufacturer=石药`）

### 2.2 Schema 改造

#### 2.2.1 `CtdTemplateNode` 新增字段
```prisma
model CtdTemplateNode {
  // ... existing fields
  isRepeatable      Boolean  @default(false) @map("is_repeatable")
  // 该节点作为"实例键"的骨架属性名清单（JSON 数组）
  // 如 3.2.S -> ['substance', 'manufacturer']
  // 如 2.3.P -> ['productName', 'dosageForm', 'manufacturer']
  // 如 2.7.3 -> ['indication']
  instanceKeyFields Json?    @map("instance_key_fields")
}
```

预置数据（seed 时写入，权威来源 = DTD）：
| elementName | isRepeatable | instanceKeyFields |
|---|---|---|
| `m2-3-s-drug-substance` | true | `["substance", "manufacturer"]` |
| `m2-3-p-drug-product` | true | `["productName", "dosageForm", "manufacturer"]` |
| `m2-7-3-summary-of-clinical-efficacy` | true | `["indication"]` |
| `m3-2-s-drug-substance` | true | `["substance", "manufacturer"]` |
| `m3-2-p-drug-product` | true | `["productName", "dosageForm", "manufacturer"]` |

#### 2.2.2 `SequenceNode` 改造
```prisma
model SequenceNode {
  // ... existing fields
  instanceIndex  Int?   @default(0) @map("instance_index") // 在实例组内的序号（0 起）
  instanceLabel  String? @map("instance_label") @db.VarChar(200) // UI 显示名，如 "阿莫西林 - 石药集团"
  // 移除原 @@index([sequenceId, templateNodeId]) 的隐式"每模板唯一实例"约束
  // 新增复合唯一约束：同一 sequence + templateNode + instanceIndex 唯一
  @@unique([sequenceId, templateNodeId, instanceIndex])
}
```

- 非可重复节点：`instanceIndex = 0`（默认值），语义不变，行为与历史一致
- 可重复节点：允许 `instanceIndex = 0, 1, 2, ...`
- `instanceLabel` 由服务端按 `instanceKeyFields` 拼接生成，展示用

#### 2.2.3 数据迁移策略
- Migration `20260425xxx_multi_instance_nodes`：
  1. 新增 `CtdTemplateNode.isRepeatable` + `instanceKeyFields`；seed 脚本回填上表 5 个节点
  2. 新增 `SequenceNode.instanceIndex` + `instanceLabel`；老数据 `instanceIndex = 0` / `instanceLabel = NULL`
  3. 替换唯一约束：删除旧隐式约束（若存在），建立 `@@unique([sequenceId, templateNodeId, instanceIndex])`
- **不丢失任何现有数据**（老实例统一映射为 index=0 的首个实例）

### 2.3 后端服务改造

#### 2.3.1 `CtdTemplateService` 新增方法
```typescript
// 为可重复节点创建新实例（复制其子树 + 空白文档）
addInstance(
  sequenceId: string,
  templateNodeId: string,  // 必须 isRepeatable=true
  initialAttributes: { substance?, manufacturer?, productName?, dosageForm?, indication? },
): Promise<SequenceNode>

// 删除实例（非首次序列需按 eCTD 生命周期标记 delete operation）
removeInstance(sequenceId: string, instanceNodeId: string): Promise<void>

// 列出某模板节点在序列下的全部实例
listInstances(sequenceId: string, templateNodeId: string): Promise<SequenceNode[]>
```

**关键规则**（遵循 eCTD 实施指南）：
- 首次序列（`sequence.sequenceType = cnsqt1` 且 `sequenceNumber = 0000`）：直接 create，operation=new
- 非首次序列新增实例：operation=new（新原料药/新制剂是"新增"行为）
- 删除实例：operation=delete，并级联对子树所有 leaf 标记 delete
- 修改实例骨架属性（`substance/manufacturer`）：**沿用现有规则**（`ctd-template.service.ts:427` Rule 3.6 — 删除旧实例 + 以 new 重建）

#### 2.3.2 `initializeSequenceTree()` 逻辑
原来每个 templateNode 建一个 SequenceNode，现改为：
- 非 repeatable 节点：照常建 1 个（`instanceIndex=0`）
- repeatable 节点：**不自动建实例**，等用户通过 UI 点击"添加原料药 / 添加制剂 / 添加适应症"按钮再建
- 但实例的**直接父节点**（`3.2` / `2.3` / `2.7` 等）必须已存在，作为"挂载点"

#### 2.3.3 Validator 改造
- `completeness rules` 仍按 templateNodeId 判断，遇到 repeatable 节点时检查"至少一个实例存在"即可满足 REQUIRED
- 实例缺关键骨架属性：新增规则 `4.3.MI.1` WARNING："原料药 X 未填写 substance 属性"
- XML 生成（`index-xml.service.ts`）：每个实例输出一个独立 element，按 instanceIndex 排序

### 2.4 XML 骨架输出

示例（3.2.S 两个原料药）：
```xml
<m3-2-s-drug-substance substance="阿莫西林" manufacturer="石药">
  <m3-2-s-1-general-information> ... </m3-2-s-1-general-information>
  <m3-2-s-2-manufacture> ... </m3-2-s-2-manufacture>
  <!-- 其余 S.3-S.7 -->
</m3-2-s-drug-substance>
<m3-2-s-drug-substance substance="克拉维酸钾" manufacturer="海正">
  <m3-2-s-1-general-information> ... </m3-2-s-1-general-information>
  <!-- 独立子树 -->
</m3-2-s-drug-substance>
```

文件路径规则：实例不同 → 子目录不同。建议用 `instanceIndex`（或 slug）作为中间目录分段：
- 当前无 instance：`m3/32-body-of-data/32s-drug-sub/...`
- 多 instance：`m3/32-body-of-data/32s-drug-sub-0/...`, `m3/32-body-of-data/32s-drug-sub-1/...`

具体 slug 规则见 `package-assembler.service.ts` 实现时再锁定（建议用 `{structure_slug}-{instanceIndex}`，避免中文/特殊字符路径问题）。

## 3. WP-13.2 详细设计 — Completeness Rule Schema 扩展

### 3.1 Schema 改造
```prisma
model CtdCompletenessRule {
  id                          String   @id @default(uuid())
  applicationTypeCode         String   @map("application_type_code") @db.VarChar(10)
  regulatoryActivityTypeCode  String   @map("regulatory_activity_type_code") @db.VarChar(10)
  sequenceTypeCodes           String[] @default(["cnsqt1"]) @map("sequence_type_codes")  // NEW
  productTypeCodes            String[] @default([]) @map("product_type_codes")           // NEW, 空数组=适用所有产品类型
  templateNodeId              String   @map("template_node_id")
  ruleType                    CompletenessRuleType     @default(REQUIRED) @map("rule_type")
  severity                    CompletenessRuleSeverity  @default(ERROR)

  templateNode CtdTemplateNode @relation(fields: [templateNodeId], references: [id], onDelete: Cascade)

  @@index([applicationTypeCode, regulatoryActivityTypeCode])
  @@map("ctd_completeness_rule")
}
```

### 3.2 Migration
- `20260425xxx_completeness_scoping`：
  1. 加列 `sequence_type_codes TEXT[]` DEFAULT `{cnsqt1}`
  2. 加列 `product_type_codes TEXT[]` DEFAULT `{}`
  3. 回填：现有 9 × 4 组=36 条规则在 schema 层等价于"仅 cnsqt1 触发"，默认值已满足

### 3.3 Validator 改造
`validator.service.ts` 的 4.3.x 检查点：
```typescript
const rules = await prisma.ctdCompletenessRule.findMany({
  where: {
    applicationTypeCode: app.applicationTypeCode,
    regulatoryActivityTypeCode: ra.regulatoryActivityTypeCode,
    // NEW 精细筛选
    sequenceTypeCodes: { has: seq.sequenceType },
    OR: [
      { productTypeCodes: { equals: [] } },          // 空数组 = 适用全部
      { productTypeCodes: { has: app.productTypeCode } },
    ],
  },
  include: { templateNode: true },
});
```

### 3.4 SECTION 容器语义
`cn-1-11` 是父节点（NodeType.SECTION），其 REQUIRED 语义应为"至少一个子 LEAF 节点非空"（`cn-1-11-1` 境内 / `cn-1-11-2` 境外 / `cn-1-11-3` 代理三选一）。

在 `validator.service.ts` 新增辅助函数：
```typescript
function isSectionSatisfied(node: SequenceNode, allLeaves: SequenceNode[]): boolean {
  if (node.isLeaf) return node.status !== 'EMPTY';
  // SECTION: 递归查找子树任意一叶子是否非空
  return allLeaves.some(leaf => isDescendantOf(leaf, node) && leaf.status !== 'EMPTY');
}
```

并在 4.3.x 规则命中 SECTION 节点时调用此函数而不是直接检查 leaf 状态。

## 5. 风险与注意事项

1. **数据库唯一约束替换风险**：`SequenceNode` 原设计隐含"sequence × templateNode 唯一"，替换为 `sequence × templateNode × instanceIndex` 后，所有依赖旧假设的查询（如 `findUnique({ where: { sequenceId_templateNodeId } })`）都必须排查。**必须** grep 整个 backend/frontend 代码库，确认没有遗漏。

2. **老数据兼容**：所有现有 Sequence 下的 SequenceNode 都会被回填 `instanceIndex = 0`，只要代码路径统一通过 `findMany` 或显式加 `instanceIndex` 条件，老数据行为不变。

3. **XML 生成路径冲突**：多实例的 `xlink:href` 必须落在不同子目录，否则会违反"同目录不重名"。打包器改造时要加 `path` 去重校验。

4. **生命周期规则交互**：删除一个原料药实例 = 给该实例下所有 leaf 标记 operation=delete；同时还要给该实例本身标记 delete（通过 DTD，父元素也带 operation 属性？— 待查，若不支持则通过删除全部子 leaf 实现）。

5. **SECTION 容器语义改变可能产生新误报**：修改后 `cn-1-11` 如果所有三个子 LEAF 都空会触发 ERROR，而之前可能根本不触发。需要跑现有 e2e 用例验证兼容性。

6. **产品类型 `cnprt1`/`cnprt2` 数据来源**：当前 Application 模型是否有 productTypeCode 字段需要确认；若无，WP-13.2 的 productType 筛选要先补模型。

7. **多适应症（5.3.5）的 `indication` 属性位于父级**：`m5-3-5-reports-of-efficacy-and-safety-studies` 的 `indication` REQUIRED 标注在父元素而非子元素（5.3.5.1/2/3/4），这意味着整个 5.3.5 子树按适应症整体重复，不是单个叶节点。实现时 5.3.5 也应被标为 `isRepeatable=true`，其 instanceKeyFields = `["indication"]`。**实施前请以 DTD 行 741-744 为准**再次确认。
